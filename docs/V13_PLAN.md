# v0.13 — 写了多少，自己看得见

**状态**：已发布（v0.13.0，2026-10-20）｜ 前置：v0.12.0 已发布（2026-10-20，详见 [V12_PLAN.md](V12_PLAN.md)）

## 一句话

`WritingStats` 从 v0.8 起就在攒一份「日期 → 净增」的账本，留一年。可这一年里只有**今天**那一格进过界面，还得先设了每日目标才显示。剩下的 364 天、连续写了多少天、写得最好的那天是哪天——账一直在，没人翻。

v0.13 把账本翻开：**一个写作日历，一年一眼看完。**

## 现状（立项前核实）

- `WritingStats` 已有 `ledger: [String: Int]`（`yyyy-MM-dd` → 净增字数），`retentionDays = 365`，`total(on:)` 可取任意一天，跨天与多文档基线都已处理
- 但只有状态栏用了 `today`：`if let stats = store.writingStats, writing.dailyGoal > 0`——没设目标连今天都看不见
- 没有任何按天的遍历接口，也没有「连续/最高/总计」这类汇总
- 数据在 UserDefaults 里，不随工作区迁移；这是账本，不是文档

**所以这一版不新增任何存储、不改记账口径**——只把已有的数字整理成能看的样子。

## 形态

- 一个「写作日历」面板（sheet），不进侧栏、不占编辑器：看数据是偶尔的事，写作时不需要它
- 上半摘要、下半热力格（一年 53 周 × 7 天），点某天看那天的净增
- 颜色从当前主题的强调色派生，深浅两套主题都跟着走

## alpha — 把账本整理成能看的东西

- `WritingStats` 加只读通道：`func total(on:)` 之外给出「最近 N 天」的逐日序列（含今天未落账的 `pending`）
- 新增 `WritingCalendar.swift`（纯函数，全部可测）：
  - `days(endingAt:count:calendar:)`：最近 N 天逐日，缺的日子补 0——**空白天与「没写」是同一件事，必须在数据层就补齐**，否则视图里到处判空
  - `level(total:goal:)`：0–4 分档。设了目标就按目标比例（0 / <50% / <100% / <200% / ≥200%），没设目标按绝对档（1 / 500 / 1000 / 2000 / 4000）
  - `streak(in:)`：从最后一天往回数连续 `total > 0` 的天数；**今天还没写时从昨天数**（一天才过了一半，不该先把连续断掉）
  - `summary(in:)`：写作天数、总净增、最高单日（带日期）、当前连续
  - `weeks(_:calendar:)`：按自然周分列，每列 7 格（周一起始，首列前面补空）——排布是纯函数，视图只负责画
  - 负增长日：`level` 归 0，但单独标出来（删字也是写过的一天，不能在格子上假装不存在）
- 测试：分档边界、streak 三种情形（今天有/今天无/中间断）、周排布不串行、负增长、空账本、365 天窗口

## beta — 写作日历面板

- `WritingCalendarPanel`：摘要四格（连续 / 本月 / 今年 / 最高单日），下面是热力格
- 热力格用 `Canvas` 画：5 档颜色由主题强调色调深浅，今天的格子描边；鼠标悬停与点击都能看「10 月 12 日 · +1,240 字」
- 底部图例（少 → 多）与一句说明：账本留 365 天、在哪
- 入口：菜单 `视图 › 写作日历…`（`⌘⇧Y`）+ `⌘K` 命令面板；状态栏的今日净增徽标也点得开（那里本来就是「今天写了多少」，往下一层就是这一年）
- 空账本不显示空网格，只一句话：先写几天，这里就有东西看了

## rc — 收尾

- 文档、README、PRODUCT、测试计数、发布

## 边界（这一版不做）

- 按文档 / 按工作区的统计：账本是应用级的，拆开要改记账口径，且「写作总量」本身就是应用级的问题
- 导出 CSV、历史导入：先让人看见，再谈搬走
- 打卡提醒、连续奖励、成就徽章：写作工具不该反过来催人写字
- 跨设备同步：账本和文档一样，只在本机

## 验收（alpha）

- [x] 空账本 → 序列全 0、`streak` 为 0、摘要不炸
- [x] 昨天写了今天没写 → `streak` 仍从昨天算起
- [x] 今天写了 → `streak` 含今天
- [x] 中间断一天 → 连续断在那里
- [x] 负增长日 → 档位 0，但标为「删过字」
- [x] 一周第一列的空位不把上周的日期串进来
- [x] 设了目标 / 没设目标 → 两套分档都按预期
- [x] 窗口取 365 天，边界不多不少

## 落地记录（alpha，2026-10-20）

- 没有新增存储，也没有改记账口径：`WritingStats.total(on:)` 早已能取任意一天，
  这版只是把它读出来。计划里写的「只读通道」到此为止——再包一层没有意义。
- 新 `WritingCalendar.swift`（纯函数）：`days`（最近 N 天，空白天补 0）/
  `level`（0–4 档，有目标按比例、没目标按绝对字数）/ `streak` /
  `summary` / `weeks`（一周一列，7 格）。
- **日期键提到 `WritingDayKey`**：账本键原来藏在 `WritingStats` 里，日历要按同一天去翻账。
  两处各写一遍迟早会漂（时区、日历标识、补零位数），提到一处两边共用。
- 两个口径决定：
  - **今天还没写不算断**——一天才过了一半，`streak` 从昨天算；今天在删字同理。
  - **最高单日平手取更近的那天**——「最近一次写到这么多」比「第一次」有用。
- 测试 665 → **682**（`WritingCalendarTests` 17 条）。
- 反向验证六组全红：`streak` 不回落昨天（2 条红）/ 档位边界改成闭区间（1 条）/
  首列不补空（2 条）/ 逐日序列倒序（9 条）/ 最高单日平手取最早（1 条）/
  负增长不算删字（1 条）。
- 写法上踩到一次自己：前两版测试把「连续序列」当成了稀疏数组传给 `streak` 和 `weeks`，
  两处都红。**这两张函数的契约是「days 连续且从旧到新」**——测试要按契约造数据，
  用 `days(endingAt:count:…)` 生成，不要手捏数组。

## 落地记录（beta，2026-10-20）

- `WritingCalendarPanel`：780×420 的 sheet。摘要四格（连续 / 本月 / 今年 / 最高单日）
  → 一年热力格 → 选中提示与图例 → 脚注（账本留 365 天、不出本机）→ 关闭。
- 热力格用 `Canvas` 画，53 列 × 7 行。**几何提成 `WritingHeatmapLayout` 纯函数**
  （`origin` / `size` / `hit`）：格子只有 10 点宽，点歪一格就是另一天，
  这是肉眼最难发现、也最该被断言的一类错。
- 深浅五档从 `Color.accentColor` 派生（0 档是 `secondary.opacity(0.12)`），
  深浅主题都跟着系统走；**今天描边**，一眼知道最右那一格是哪天。
- **删字的那天画空心格**：`level` 归 0 会和「没写」撞成一样，
  但删字日不是空白日——不填色，也不能假装它不存在。
- 千分位自己数（`WritingCalendarText.grouped`）：`formatted()` 的分组符跟着
  系统语言走（中文 `1,240`、德语 `1.240`），测试没法写死。负数用真正的减号 `−`。
- 入口三处：菜单 `视图 › 写作日历…`（`⌘⇧Y`，挨着版本历史的 `⌘Y`）、`⌘K` 命令面板、
  状态栏「今日 x / y 字」徽标点开——那里本来就是说「今天」，往下一层就是这一年。
- 空账本不画空网格：一句话「还没有记账 / 写上几天，这里自然就有了」。
- 版式用 `NSHostingView` + `cacheDisplay` 渲染成图核对过（临时探针，用完即删）：
  最右一列是本周、今天描边、删字日空心、图例五档都对得上。
- 测试 682 → **691**（`WritingCalendarPanelTests` 9 条）。
- 反向验证三组全红：命中不拦越界列（1 条）/ 千分位不进位（5 条）/
  负号退化成连字符（1 条）。
