# v0.9 — 成文的那一半

**状态**：进行中（2026-10-18 立项）｜ 前置：v0.8.0 已发布（2026-10-18，详见 [V08_PLAN.md](V08_PLAN.md)）

## 一句话

v0.8 把**思绪**那一侧的手感补完了：回车、Tab、粘贴、字数。可这个产品的另一半叫**成文**——预览自 v0.4 之后，除了主题换色，几乎没动过：字号、行距、版心宽度都写死在样式表里，读者读自己写的东西，用的还是同一个尺寸。

v0.9 只做一件事：**让读的那一半也趁手**。

## 现状（立项前核实）

- `StyleSheet.baseCSS` 里 `body { font-size: 16px; line-height: 1.75 }`、`#wtmd-content { max-width: 760px }`——全是常量，主题只能改颜色与字体栈
- 预览与源码在分栏里各滚各的：源码有 `cursorLine`，预览有「顶部落在哪个块」的 `PreviewAnchor`，两边从不相认
- `⌘F` 在预览里没有任何痕迹：命中区间是源码的 UTF-16 偏移，预览侧看不到「哪一段里有」
- 打印/PDF 用 `@media print` 一律 `padding: 0; max-width: none`，没有页边距、页码，导出的 PDF 与屏幕上的版式两回事

## P0-1 — 版式可调（alpha）

- `TypesettingSettings`：版心宽度、正文字号、行距三档，defaults 可注入，界面里滑动即生效
- 三个值走 CSS 变量（`--wtmd-measure` / `--wtmd-font-size` / `--wtmd-line-height`），`baseCSS` 里只留默认值——主题社区那套 CSS 不受影响
- 独立 `<style id="wtmd-layout">` 层，与 `#wtmd-theme` 分开：切主题不能把读者的版式一起冲掉；反之亦然
- 热更新走 `__wtmdSetLayout`，只换变量文本、不重载页面（滚动位置与图表都不动）
- 设置里可一键回到默认（760 / 16 / 1.75）

## P0-2 — 两侧联动（beta）

- 分栏时源码光标所在段 → 预览滚到对应块（反向也成立：预览滚到哪一块 → 源码对应行高亮/滚动）
- 依赖渲染层给每个顶层块带**源码行号**（`data-wtmd-line`），`PreviewAnchor` 的块下标因此可以反查回行
- 只在分栏模式下生效；单栏编辑或预览时不联动，别让读者在打字时被拽走
- 用户手动滚动的一方在短暂时间内优先，避免两边互相推

## P0-3 — 打印与 PDF（rc）

- 打印样式可设：页边距、页码（右下）、可选首行标题
- PDF 导出沿用当前版式（版心宽度在纸上归一为页宽减页边距）
- 屏幕上看到的与纸上印出来的，字号与行距一致

## 边界（这一版不做）

- 富文本所见即所得（v0.4 结论不变）、拖拽重排
- 主题编辑器 / 主题市场
- 多窗口（架构级，单独一版再谈）
- 预览内的批注、划线、朗读

## 验收

- [ ] 三个版式值滑动即生效，切主题不互相冲掉，重启后还在
- [ ] 分栏联动双向可用，单栏时不打扰写作，手动滚动能夺回控制权
- [ ] 打印/PDF 有页边距与页码，版式与屏幕一致
- [ ] 既有不变式不破：`#wtmd-content` 顶层子节点数 == 块数、位置记忆、增量渲染、导出三端一致

## 进度日志

- 2026-10-18 **v0.9.0-alpha 完成**（issue #92）
  - **`TypesettingSettings`**（新文件）：版心宽度 480–1100px、字号 14–22px、行距 1.4–2.2，
    defaults 可注入；`css` 生成时把越界值收敛回区间（手改过的 defaults、旧版本遗留值都不会撑坏版面）
  - **样式层**：`baseCSS` 里三个常量换成 `var(--wtmd-*, 旧默认值)`——主题文件与自定义 CSS 一行不用改；
    独立的 `<style id="wtmd-layout">` 与 `#wtmd-theme` 分层，切主题不会冲掉读者的版式
  - **热更新**：`__wtmdSetLayout` 只换变量文本，页面不重载（DOM 探针用例守住节点不被替换）；
    元素缺失时现建一个，导出文档里同一段脚本也能跑
  - **界面**：设置页新增「阅读版式」一节，三个滑块 + 数值 + 恢复默认；面板加高到 460×680 才放得下
  - 导出 HTML / 打印不传 `layoutCSS`，产物与从前逐字一致（rc 再接管纸上版式）
  - 测试 490 → **501**（偏好 6 + 样式装配 2 + 离屏 WKWebView 4）；反向验证四组全红：
    样式表退回硬编码、热更新改成重写 DOM、换主题顺手清版式层、不输出版式层
  - 坑：行距是乘出来的浮点（18 × 1.9 = 34.2），浏览器给的是舍入值——断言要按数值容差比，别比字符串
  - WKWebView 的内容不会进 `cacheDisplay` 的位图（离屏限制），版式只能靠计算样式断言守；设置面板已渲染成图人工复核

- 2026-10-18 **v0.9.0-beta 完成**（issue #94）
  - **行号从解析器一路带到预览**：`MarkdownParser.parseNumbered` 多返回一份与块平行的
    「原文行号」。脚注定义行是解析前剥掉的，拿过滤后的下标充数会让后面每一块整体上移；
    `RenderResult.blockLines` 与 `blocks` 同源，脚注区（渲染时追加）记 `-1`。
  - **行号不进块 HTML**：块字符串是 `BlockDiff` 的比较基准。一旦把行号写进标签，
    在文首插一行就会让后面每一块都「变了」，增量渲染退化成整篇重画。改成
    `__wtmdSetLines` 把行号挂在 DOM 节点的自定义属性 `el.__wtmdLine` 上——不参与
    innerHTML 比较；每次 `__wtmdUpdate` / `__wtmdUpdateRange` 之后重打一遍即可。
  - **判权**：`SyncScrollState`（来源 + 0.5s 静默窗口）。一边驱动另一边之后，另一边的
    回报一律当回声丢掉；窗口一过、读者真去滚那边了，控制权就归它。`SplitSyncController`
    只做翻译（谁动了 → 另一侧滚到第几行），时钟可注入，纯逻辑可测。
  - **两侧行为**：源码光标换段 → 预览把那一块滚到顶部（第一块特殊处理为回顶，否则会停在
    body 上内边距下面，看着像「差一截没滚上去」）；预览滚到哪 → 源码 `revealLine`
    **只滚不改光标、不抢焦点**（读者只是在看，不是要在这里写）。
  - **只在分栏生效**；预览刚装载的 0.6s 内不报行号——恢复上次位置本身会触发 scroll 事件，
    那一帧推源码会把刚恢复好的位置顶回文首。
  - 测试 501 → **539**（块行号 13 + 判权与控制器 14 + 源码 reveal 4 + 离屏 E2E 7）。
    反向验证四组全红：行号退化为过滤后下标、增量后不重打行号、去掉静默窗口、联动顺手改光标。
  - 坑：`#expect(state.accept(...))` 不能直接包 mutating 调用（宏闭包里是 immutable），
    先赋给 `let` 再断言。
  - 坑：「滚过去看看落在哪」守不住增量重打行号——旧行号表偏小，照样能把人送到正确的块上。
    必须逐节点核对 `__wtmdLine` 与渲染结果是否一一对齐（`misalignedLineJS`）。

- 2026-10-19 **v0.9.0-rc 完成**（issue #96）
  - **打印换了条路，不走 `NSPrintOperation`**：实测它在离屏 / 无窗口环境会死循环在
    `displayIfNeeded`（测试进程里 45 秒不动、内存涨到 1.2G，无论视图挂不挂窗口）。
    改成「WebKit 整篇出一条长 PDF（`createPDF`）→ `PrintPagination` 按块算切点 →
    **逐页**再让 WebKit 出（`WKPDFConfiguration.rect`）→ `PDFSlicer` 等比贴进 A4 正文框 →
    `PDFPageNumberer` 叠页码」。逐页出而不是整篇裁：裁切只是遮住，字还在文件里——
    每页复制出来的文字应该是「这一页的」。
  - **字号不随页边距缩**：96dpi 的 CSS px 到 72dpi 的 pt 正好 ×0.75（16px → 12pt）。
    边距只改一页装多少字（版心 = 页宽减边距，再 ÷0.75），不该把字越缩越小。
  - **切点只在块与块之间**：量每个顶层块的上下边界（块间空隙归上一块，否则页底会
    误以为还放得下一行）；单块比一页还高（长表格、长代码）只能硬切。
  - **`getDrawingTransform` 不可靠**（会居中而不是顶对齐），贴片的手写 CTM 用
    合成 PDF 的像素级探针验证过：黑条落在期望的位置上。
  - **就绪探测**：`didFinish` 只说明 DOM 到了，mermaid / KaTeX / 图片还在异步渲染；
    打印文档里注入 `__wtmdPrintReady()` 轮询（上限 5s，兜底不阻塞导出）。
  - **纸上版式层不写页边距**：CSS 里再留 padding 会和 A4 正文框叠成双层边距；
    `html/body` 的 margin/padding、版心居中全部归零。
  - 坑：PDFKit 抽出来的文字在折行处插换行，且 WebKit 字体子集把部分汉字映成
    **康熙部首**（⽤/⼦/⼏/⻚，NFKC 也救不全 `⻚`）——「段落没被切开」的断言
    别去比原文，改比「每页第一行是否一段的开头」。
  - 测试 539 → **572**（分页 6 + 纸的几何 4 + 设置/样式/页码 15 + 离屏 E2E 8，
    其中「字都在正文框里」逐字形采样、「每页都是 A4」「页码带总页数」「边距大页数多」
    「字号大页数多」「标题可选」）；样张（标题/清单/表格/代码/引用 + 40 段）逐页人工复核。
