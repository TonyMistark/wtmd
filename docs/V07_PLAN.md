# v0.7 — 一间书房，也要能摆书

**状态**：进行中（2026-10-17 立项）｜ 前置：v0.6.0 已发布（2026-10-17，详见 [V06_PLAN.md](V06_PLAN.md)）

## 一句话

v0.3 给了文件夹工作区，v0.6 让里面的话能被找回来——但到目前为止，那间书房**只能看，不能摆**：
在树里新建不了一篇，改名要跳去访达，删掉更是连入口都没有。v0.7 把文件树从「目录索引」变成
「能动手的书架」。

## 现状（立项前核实）

- `WorkspaceScanner` 只收 `.md`/`.markdown`，且**不含任何 Markdown 的目录整个不显示**——
  「新建文件夹」若落在这种规则下会瞬间消失，所以这条规则必须先改
- `WorkspaceStore` 只有 `open` / `close` / `reload` / `select` / `reveal` / `setExpanded`，没有任何写操作
- 未命名文档 `⌘S` 的 `NSSavePanel` 不认工作区，得自己导航到那个文件夹
- 树行没有 `contextMenu`，点击只有「打开」一个动作

## P0-1 — 文件操作与改名跟随（alpha）

- **`WorkspaceFiles`（纯函数，可单测）**：新建文稿 / 新建文件夹 / 重命名 / 移到废纸篓
  - 新建用 `未命名.md`、`未命名 2.md`… 自动编号，绝不覆盖已有文件
  - 重命名只改名字、不换扩展名（用户没写 `.md` 时补上）；名字里的 `/` 与首尾空白拒绝或清理
  - 删除走 `FileManager.trashItem`——**进废纸篓，不是 `unlink`**，误删还能捞回来
- **`WorkspaceStore` 加四个动作 + 本地状态跟随**：`expandedPaths`、`selection`、`Session` 里的
  路径都要在改名后 remap，否则下次启动会去开一个不存在的路径、展开状态也会凭空收起来
- **`DocumentStore` 跟随**（关键不变式）：
  - 当前这一篇被改名 → `fileURL` 跟着走，**`savedSnapshot` / 撤销栈 / 渲染代数都不动**——
    内容没有变，变的只是它叫什么
  - 当前这一篇被移到废纸篓 → 内容留在编辑器里、文档转成未命名草稿并立即写草稿盘；
    **不能**先 flush 再删（那等于把字写进废纸篓）
- **树行右键菜单**：文件（打开 / 重命名 / 在访达中显示 / 拷贝路径 / 移到废纸篓）；
  文件夹（新建文稿 / 新建文件夹 / 重命名 / 在访达中显示 / 拷贝路径 / 移到废纸篓）
- **行内重命名**：不动弹窗，直接在那一行变成输入框；`↩` 提交、`esc` 取消、失焦提交；
  被拒原因（重名 / 非法字符）就地在行下显示红字
- **扫描器规则改一条**：目录只要不是隐藏项/包就显示，**空目录也显示**（否则新建的文件夹看不见）；
  另外跳过 `node_modules` / `Pods` / `DerivedData` / `.build` 这类噪音目录，避免把整棵树撑爆

## P0-2 — 新建落在手边（beta）

- `⌘N` 在工作区里 = **在选中目录下建一篇真的文件并打开**（选中文件则建在它旁边），
  而不是先给一篇未命名草稿等读者自己另存；没有工作区时行为不变
- 未命名文档 `⌘S` 的另存面板默认落在当前工作区目录
- 文件夹拖拽移动（拖到另一个文件夹即移动，拖出窗口不做事）；移动后当前文档与展开状态同样跟随

## P0-3 — 外部改名与删除（rc）

- 当前这一篇在访达里被改名/移走：watcher 发现后不要立刻弹横幅，先按「同目录、同大小、
  同修改时间」找一次，能找到就静默跟随
- 最近文件里已不存在的条目在启动时清理（`RecentFiles` 目前只过滤不存在的路径，但改名后会留下旧路径）
- P2 挑 1 项（v0.6 顺延：主题社区页 / 界面英文化）

## 边界（这一版不做）

- 多选与批量操作（批量删是危险动作，要配确认流，另开一版）
- 模板、每日笔记、文件名规则引擎
- 在树里重命名**文件夹**并同步更新正文里的相对链接（链接语义要单独设计）

## 验收

- [ ] 在工作区里能新建文稿/文件夹、改名、移到废纸篓，全部即时反映到树与磁盘
- [ ] 改名或删除的正是当前打开的那一篇时，编辑内容一个字不丢；磁盘上的其他文件不受影响
- [ ] 重名、非法字符、无权限都有就地说明，不弹模态对话框
- [ ] 空目录可见；隐藏目录与噪音目录不可见
- [ ] 既有不变式不破：文档内查找、工作区搜索、预览增量渲染、四套端到端用例全绿

## 进度日志

- 2026-10-17 **v0.7.0-alpha 完成**（issue #78）
  - 新文件：`WorkspaceFiles`（纯函数：新建 / 改名 / 废纸篓 / 唯一编号 / 名字校验）、
    `WorkspaceTreeView`（从 ContentView 拆出的文件树——它自己的状态自己拿，也才能单独渲染快照）
  - **`WorkspaceStore` ↔ `DocumentStore` 走协议**：`WorkspaceFileEvents`（`documentDidMove` /
    `documentWasTrashed`），App 装配、测试为 nil——谁也不拥有谁
  - **改名跟随的关键取舍**：只改路径，`savedSnapshot` / 撤销栈 / `renderGeneration` 都不动——
    重渲染会把读者的滚动位置和光标一起吞掉；`knownModificationDate` 刷到新路径
  - **删除走废纸篓**（`FileManager.trashItem`），且当前文档被删时**绝不先 flush**——
    内容改走草稿盘，`savedSnapshot` 置空让文档保持「脏」，退出时还会写一遍
  - **扫描器规则改了一条**：完全空的目录也进树（新建的文件夹必须当场看得见）；
    代价是「只有图片的 assets/ 仍然隐藏」这条边界保留了——子树里有 Markdown 才显示的
    老规则对非空目录继续生效
  - **`/var` vs `/private/var` 第三次出现**：`contentsOfDirectory` 返回的是解析过符号链接的
    路径，而面板/会话来的可能没解析——这次直接把 `canonicalPath` 收进 `WorkspaceStore`，
    `isDescendant` / `contains` / `reveal` / `select` / 最近文件比较全部归一（v0.5、v0.6 各踩过一次）
  - `⌘N` 在工作区里改为**直接在选中目录落盘**并就地起名（`pendingRename` → 行内输入框）；
    没有工作区时仍是未命名草稿。未命名文档 ⌘S 的面板默认落在当前工作区
  - 测试 338 → **365**（文件操作 10 + store 动作 7 + 文档跟随 5 + 会话迁移 2 + 树快照 1）；
    反向验证四组：改名不迁移状态、删前不写草稿、空目录不可见、会话位置不迁移——对应用例全红
  - 快照 `/tmp/wtmd-workspace-tree.png` 已人工复核（空文件夹可见、当前文档在列）
- 2026-10-17 **v0.7.0-beta 完成**（issue #80）
  - 新文件 `PathKey`：把「是不是同一个文件」的判据从 `WorkspaceStore` 里抽出来，做成**不依赖主线程**
    的纯函数——`WorkspaceFiles` 是 nonisolated 的，直接问 `@MainActor` 的 store 编不过。
    `WorkspaceStore.canonicalPath` 保留为转发入口，最近文件比较、树高亮、文件操作从此同一把尺子
  - 新文件 `WorkspaceDrag`：拖拽载荷是**一行 UTF-8 路径** + 自定义 UTI `cn.wtmd.workspace-row`
    （声明写进 `make-app.sh` 的 Info.plist）。不接 `public.file-url` 是有意的：拖拽会真的改磁盘，
    从访达误拖一堆文件进来不该是「⌘Z 一下就能回去」的事
  - `WorkspaceFiles.move(_:into:)`：不改名；同名**报错不覆盖**（拖拽容易手滑，手滑不该有删除的后果）；
    拖进自己或自己的子孙直接拒；落点就是原父目录时原样返回，调用方据此跳过状态迁移
  - `WorkspaceStore.move` 复用 alpha 的 `remapPaths` 链路：展开状态、高亮、会话路径、当前文档
    一起搬；落点目录**顺手展开**——东西移进去却看不见，和丢了没区别
  - **树的文件行从 `Button` 换成 `Label` + `onTapGesture`**：macOS 上按钮会吃掉拖拽手势，
    那样这一行永远抓不起来
  - 拒绝与失败就地一行红字、4 秒自消，仍然不弹模态；悬停染一层强调色（只染底色不加边框，
    否则整棵树在拖拽时会抖一下）
  - 顺手修掉一个老边界：`ancestors(of:upTo:)` 会一路走到文件系统根，把**工作区外面**的目录
    塞进展开状态（`⌘N` 建在根上时就在发生，只是没人看）。改成「只走到工作区根为止」
  - 测试 365 → **377**（纯函数 6 + 载荷 1 + 状态迁移 5）；反向验证六组：同目录不短路、
    不拦「移进自己」、落点不展开、载荷冒充 file-url、祖先走到根外、移动不迁移状态——对应用例全红
