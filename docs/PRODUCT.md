# wtmd — Where Thoughts Meet Documents

> 一个开源、本地优先的 macOS Markdown 写作与阅读工具。
> 思绪落下的一刻，成文已然成型。

## 1. 产品故事

**wtmd** 是 "**W**here **T**houghts **M**eet **D**ocuments" 的缩写。

写作工具长期存在一道裂缝：一边是纯文本编辑器——自由、可移植，但你必须在脑中想象排版结果；另一边是富文本处理器——所见即所得，但文件被锁进私有格式，离开这个软件便寸步难行。

wtmd 相信这两者本不该冲突。**Markdown 本身就是排版语言**——敲下 `#` 与空格的瞬间，一篇文章的骨架已经确立。我们要做的，是把这层转换变得毫无摩擦：你专注于思绪，wtmd 负责呈现。

当收费的高墙立在写作者与他们的工具之间时，我们选择开源这条路。wtmd 以 MIT 协议发布，代码公开、格式开放、数据永远属于你自己。

### 中心思想的产品落地

「思绪与文档相遇」不是一个口号，而是界面上可被指认的设计决策：

| 落点 | 设计 | 思想的体现 |
|---|---|---|
| 双模式命名 | 源码模式叫「思绪」，预览模式叫「成文」 | 两种视图不再是技术术语（edit/preview），而是写作过程的两端 |
| `⌘/` 切换 | 切换的瞬间配轻柔淡入淡出 | 相遇是一个瞬间——思绪化为成文的那一瞬 |
| 欢迎页 | 断续虚线 → wtmd → 连续实线 | 纷飞的思绪流经工具，化作沉稳的文档 |
| 空文档文案 | 「落笔即成文 —— 输入第一行思绪」 | 空白不是虚无，是即将成文的思绪 |
| 按钮文案 | 「记下思绪」而非「新建文件」 | 用户的动作被描述为写作，而非文件操作 |
| 保存哲学 | 草稿自动保存、文件永在本地 | 思绪不该因为忘了保存而丢失，文档不该因为格式而失去自由 |

## 2. 设计哲学

1. **写作即排版（Write is Render）**
   源码与排版不是两个割裂的世界，而是同一份文本的两种视图。切换应当即刻发生、无感发生。语法符号在预览中隐去，在源码中归来——文本本体从未改变。

2. **极简无干扰（Invisible Tool）**
   最好的工具是让人忘记它存在的工具。界面只在需要时出现：没有多余的面板、没有花哨的动画、没有社交与订阅的打扰。心流比功能更重要。

3. **纯文本本质（Plain Text Forever）**
   底层永远是标准 Markdown（兼容 GitHub Flavored 方言）。任何时代、任何工具都能打开你的文件。没有私有格式，没有数据绑架。

4. **本地优先（Local First）**
   文件躺在你的磁盘上，通过 Finder 与其他工具无缝协作。不强制云端、不要求账号。隐私不是功能，是默认。

5. **开放可塑（Open by Design）**
   MIT 开源协议。主题是开放标准，欢迎社区贡献与衍生。

## 3. 目标用户

- 技术写作者：撰写文档、博客、README、技术方案
- 知识工作者：笔记、周报、长文阅读与整理
- 开发者群体：偏好纯文本与命令行生态、在意数据主权的人

## 4. MVP 功能规格（v0.1）

### 4.1 双模式视图

| 功能 | 说明 |
|---|---|
| 思绪（源码）模式 | 等宽字体编辑，语法高亮（标题/强调/代码/链接/引用等） |
| 成文（预览）模式 | 完整排版渲染，阅读级字体与版式 |
| 即时切换 | ⌘/ 快捷键 + 工具栏切换（「思绪 ⇄ 成文」），带轻柔过渡动画，光标滚动位置尽力保持 |
| 无缝感知 | 两种模式同一窗口，切换不跳转、不闪白 |

### 4.2 Markdown 渲染（自研解析器，零第三方依赖）

- 块级：标题 h1–h6、无序/有序/任务列表、引用、代码块（围栏式+语言标注）、分隔线、表格（GFM）
- 行级：粗体、斜体、行内代码、链接、图片、删除线、自动链接
- 扩展：任务列表复选框、脚注（v0.2）

### 4.3 大纲导航

- 侧栏自动生成标题层级树（可折叠）
- 点击跳转到对应章节
- 长文写作的结构地图

### 4.4 文件管理

- 打开/保存 .md 文件（⌘O / ⌘S）
- 最近文件列表（应用重启保留）
- 未保存修改标记（标题栏 • 圆点）
- 自动保存当前编辑内容（草稿不丢）

### 4.5 导出

- HTML：完整独立文件（内联 CSS 主题）
- PDF：打印级排版输出

### 4.6 主题

- 内置浅色/深色两套预览主题，跟随系统外观
- 开放 CSS 主题格式（v0.2 支持用户自定义导入）

## 5. 非目标（v0.1 明确不做）

- 实时协作 / 云同步 / 账号体系
- 双向链接与知识库管理（那是另一类产品的战场）
- 插件系统
- WYSIWYG 所见即所得编辑（v0.3+ 再评估，技术复杂度最高）
- 移动端

## 6. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| UI | SwiftUI（macOS 14+） | 原生体验、轻量、与系统深浅色无缝集成 |
| 源码编辑 | NSTextView (ViewRepresentable) + NSAttributedString 正则高亮 | SwiftUI TextEditor 无法胜任语法高亮与精细控制 |
| 预览渲染 | WKWebView + 注入 HTML/CSS | Web 是 Markdown 排版的母语，主题生态天然开放 |
| 解析器 | 自研 WTMarkdownKit（纯 Swift） | 零依赖、可测试、渲染与大纲共用一棵 AST |
| 打包 | Swift Package（library + app target） | 单仓清晰，CI 友好 |

### 模块划分

```
wtmd/
├── Package.swift
├── Sources/
│   ├── WTMarkdownKit/        # 核心库：解析器 + AST + HTML 渲染 + 大纲提取
│   └── wtmd/                 # App：UI、编辑器、预览、文件管理、导出
├── Tests/
│   └── WTMarkdownKitTests/   # 解析器单元测试
└── docs/
    └── PRODUCT.md
```

### 关键技术点

- **解析器**：两阶段（块级切分 → 行级内联展开），产出轻量 AST；大纲直接从 AST 提取标题，保证与预览零偏差
- **模式切换的位置保持**：源码↔预览切换时按标题/段落偏移估算滚动锚点
- **性能**：解析在后台队列，主线程只做渲染注入；长文档增量更新（v0.2）
