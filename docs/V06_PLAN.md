# wtmd v0.6 规划 — 从写完一篇，到找得到那句话

> v0.5 让写作者不再因为切换而丢位置；v0.6 解决另一个更日常的摩擦：**东西写进去了，却找不回来**。
> 一份三万字的书稿里想确认「这个词我之前怎么说的」，现在只能手翻——这是一个写作工具的硬伤，
> 不是锦上添花。

**状态**：规划中（2026-10-17 立项）｜ 前置：v0.5.0 已发布（2026-10-17，详见 [V05_PLAN.md](V05_PLAN.md)）

## 版本主题

| 特性 | 哲学落点 |
|---|---|
| 文档内查找替换 | 纯文本本质——文件可以被 `grep`，工具里更该能 `⌘F` |
| 工作区全文搜索 | 本地优先——整个书房都在磁盘上，搜索不该需要索引服务或联网 |
| 冲突未解决时保全本地版本 | 写作即排版——读者不该为了「保住一段话」先学会理解冲突 |

## 现状取证（代码事实，v0.5.0）

- `CommandCatalog` 共 22 条命令，`grep -i find` 一条也没有：**`⌘F` 按下没有反应**。
  系统 find bar 其实是开着的（`usesFindBar = true`，v0.1 起就有），但它只做字面量查找、
  没有正则与替换、没有命中计数，也接不进我们自己的高亮体系——alpha 把它关掉，自绘一条
- `EditorTextView.highlight`（`EditorTextView.swift:513`）在每次编辑后**重建全部属性** → 查找高亮**不能**写 textStorage，否则下一次按键就被冲掉
- 专注模式已经给出了正确范式：`layoutManager.addTemporaryAttribute`（`EditorTextView.swift:373`，注释写明「不碰 textStorage」）→ 查找高亮走 `.backgroundColor` 临时属性，与专注的 `.foregroundColor` 互不干扰，两者可同时开
- 预览是 WKWebView + 块级增量 DOM：`.mark` 只能包在块**内部**，**不得增删 `#wtmd-content` 顶层子节点**，也不得往 `document.body` 挂任何东西
- `DocumentStore.jump(to:)`（`DocumentStore.swift:232`）只接受 `OutlineItem`（标题）→ 搜索命中需要「行 + 列」的落点，得把它泛化一层
- `WorkspaceScanner` 已能递归扫出 `.md`，`DirectoryWatcher` 已在监听变更 → 全文搜索**不需要**新建索引基础设施
- **快捷键占用**：`⌥⌘F` 已是专注模式（v0.3 起的肌肉记忆，不动），替换用 `⌥⌘R`（R 记 Replace）

## P0-1 — 文档内查找替换（`⌘F` / `⌥⌘R`）✅ alpha 已完成

**用户故事**：我在第 200 段想确认前面某个词怎么用的，按 `⌘F` 输入，命中处高亮、回车跳到下一处、
`esc` 回到原光标位置。

- 自绘一条轻量查找条（底部状态栏之上，同一套材质与字号），**不用 `NSTextView` 自带 find bar**：
  自带条是系统样式、与「思绪/成文」的气质割裂，且替换只支持字面量、不给正则
- 选项：区分大小写、全词匹配、正则；显示「第 n / 共 m 项」
- **高亮只走 layout manager 临时属性**：全部命中用一层浅黄 `.backgroundColor`，当前命中用强调色描边；
  文本变过（属性重建）后重铺一次——`applyFocusFull` 已经证明这条路可复用
- 替换：单次替换（替换并跳到下一处）/ 全部替换。**全部替换必须是一次撤销**：
  一次 `shouldChangeText` + `replaceCharacters` + `didChangeText`，不逐处替换
- 预览侧也能找（只读）：命中区间由 Swift 侧算好（与源码同一份 `FindSession`），
  通过现有 `evaluateJavaScript` 在块内包 `<mark>`；**搜索结果变化时先清旧 mark 再打新 mark**，保证幂等
- `esc` / 「完成」关闭时收掉全部临时属性，光标回到按下 `⌘F` 之前的位置
- 文本变化后自动重算（文档很短，重算是 O(n) 的 `range(of:)` 循环；>400k 字符同 `highlight` 一样跳过）

**风险**：IME 组合期间不能触发查找（组合中的 marked text 不是文档内容）；与专注模式叠加时要确认
两种临时属性不互相清除——这两条都要有测试。

## P0-2 — 工作区全文搜索（`⌘⇧F`）✅ beta 已完成

**用户故事**：这个文件夹里我哪篇提过「XX」？结果列出来，点一条直接跳到那一段。

- 入口：`⌘⇧F` 打开搜索面板，复用 `CommandPalette` 的交互骨架（输入即搜、↑↓ 选择、回车打开）
- 搜索：递归遍历工作区内的 `.md`，逐行匹配；**不做持久化索引**——先实测，500 个文件一遍
  在 SSD 上是几十毫秒的量级，超时才引入索引（那是 v0.7 的事）
  - 跳过 `.git` / `node_modules` / 隐藏目录；单文件 > 2 MB 跳过并计数告知
  - 大小写不敏感 + 变音符号不敏感（`NSString.range(of:options:)`），不做中文分词
- 结果：按文件分组，每条显示命中行 + 前后一小段上下文，命中词高亮；上限 200 条并提示「已截断」
- 动作：回车 → `open(url:)` → 泛化后的 jump 落到「行 + 列」→ 光标选中该命中词
- 取消：面板关闭即取消；遍历在后台，**不阻塞主线程**（复用 `renderGeneration` 式的代际守卫丢弃过期结果）

**风险**：大目录（>5000 文件）遍历期间用户继续打字，必须可取消；
空查询不能扫全盘（直接返回空结果）。

## P1 — 冲突未解决时切换文档会丢本地版本（补 v0.5 的已知边界）

issue #63 里记着这个洞：冲突状态下直接切走，本地那份只存在于内存里，换回来就没了。两条候选：

- **A（推荐）**：切走前把本地版本写到 `~/Library/Application Support/wtmd/conflicts/<文件名>-<时间戳>.md`，
  并在状态栏留一个「有 1 个未合并的本地版本」入口；回来时可直接另存或丢弃
- B：切走时把冲突横幅升级成模态三选（保留 / 放弃 / 取消切换）——但写作工具不该弹窗，只作为兜底

## 不变式与红线（开工前先读）

1. **查找高亮绝不写 textStorage**——只能走 layout manager 临时属性，否则每次按键被 `highlight` 冲掉
2. **预览侧只允许块内改 DOM**：`#wtmd-content` 顶层子节点数 == 顶层块数；`document.body` 只能有它一个子元素
3. **IME 组合期间不打断**：查找/替换不得在 marked text 存在时改文本，`insertAtCursor` 前先 `unmarkText()`
4. **全部替换是一次撤销**，且替换后高亮与 diff 都要重算，不能留下指向旧偏移的 mark

## 进度日志

- 2026-10-17 **v0.6.0-alpha 完成**（#69 / PR #70）：文档内查找替换
  - 新文件：`FindEngine`（纯匹配，无 UI）、`FindController`（状态机）、`FindBar`（自绘查找条）。
    规划里「预览侧高亮」挪去了 beta——源码命中数与渲染文本命中数天然不一致
    （`**粗体**` 的星号在预览里不存在），两侧各自按所在视图算才诚实
  - **高亮只走 `layoutManager` 临时属性**：`findHighlightIsTemporaryAndSurvivesARebuild`
    同时断言「临时属性在、textStorage 里没有」，且模拟一次按键重建高亮后仍在
  - **替换必须经过 `NSTextView`**：`shouldChangeText` + `textStorage.replaceCharacters` +
    `didChangeText` 成对调用才算一步撤销——全部替换因此也是 `⌘Z` 一步
  - **一个真 bug 被测试逼出来**：`ReplaceRequest` 执行完不清，`⌘/` 重建编辑器会拿同一个
    区间**再改一遍**（那时它指向别的字）。编辑器执行完回调 `onReplaceApplied`，
    store 异步清掉
  - **替换成同样的文本**（「甲」→「甲」）内容没变，`attach` 里 `changed || resume != nil`
    两个条件都要走重扫，否则「替换」永远停在同一处
  - 快捷键落定：`⌘F` 查找、`⌥⌘R` 替换（`⌥⌘F` 归专注模式，加了「无两条命令共享快捷键」
    的守门用例）
  - 预览模式按 `⌘F` 自动切到对照——命中的高亮只存在于源码侧，切过去才看得见
  - 快照用例的坑（两个）：`ImageRenderer` 会把 `TextField`/`Button` 画成黄色占位块
    （离屏没有 AppKit 上下文），换 `NSHostingView` + `cacheDisplay` 才是真渲染；
    画布要用 `fittingSize` 贴合，且**像素断言会被显示倍率绊倒**——CI 是 1x、本机 2x，
    一律换算回点数再比（首跑 CI 双红就是这条）。两条形态（查找 / 替换）渲染图都人工复核过
  - 测试 254 → **288**（引擎 14 + 状态机 9 + 编辑器 7 + 快照 2 + 命令 2）；
    反向验证三组：高亮写进 textStorage、替换直接赋值不记账撤销、导航不绕回——对应用例全红
- 2026-10-17 **v0.6.0-beta 完成**（#71 / PR #72）：工作区全文搜索 + 行列跳转
  - 新文件：`WorkspaceSearch`（纯扫描引擎）、`WorkspaceSearchController`（防抖 + 代际守卫 + 可注入扫描实现）、
    `WorkspaceSearchPanel`（复用命令面板骨架：输入即搜、↑↓ 绕回、↩ 打开、esc 关闭）
  - **不做持久化索引**，实测（Debug 构建，本机）：500 文件 × 120 行完整扫一遍 ≈ 300ms，
    打包走 `-c release` 后远低于这个数；扫描在后台任务里跑，主线程无感
  - **正在编辑的那一篇以内存内容参与搜索**（`liveDocument` 覆盖）：磁盘副本可能还停在上一次
    自动保存，「刚敲下的词搜不到」是唯一不能接受的答案
  - **一个真 bug 被 URL 相等绊出来**：枚举器会把 `/var/...` 改写成 `/private/var/...`，而 URL
    相等是字面比较——内存覆盖与相对路径的归属判断都要先把两边 `resolvingSymlinksInPath()`
    归一到同一拼法，否则「正在编辑的那一篇」会被当成另一篇（v0.5 的 `allParts` 教训换了个马甲又来）
  - `JumpRequest` 泛化到「行 + 列」：`column` / `length` 默认 0，大纲跳转的调用点一行没改；
    编辑器新增 `reveal(_:)` 让命中停在大约三分之一处，`scrollRangeToVisible` 只保证「看得见」，
    命中贴着底边时上半句在屏幕外
  - **带落点打开时不回填上次记住的位置**：读者刚指名要找哪一句，把他送回上次停下的地方等于作废这次搜索；
    同一篇的命中不重载文档（会吞滚动位置），只送光标过去
  - **测试里的固定等待在并行跑批时会撞车**：`sleep 700ms` 断言在隔离单跑时绿、全量跑时红——
    改成「轮询等新结果落地 + 再留半秒给旧结果回来」，与 v0.3 起的轮询约定一致
  - 快捷键落定：`⌘F` 这一篇、`⇧⌘F` 这间书房，同一条命令的两个范围；守门用例已有「无共享快捷键」
  - 测试 288 → **314**（引擎 12 + 状态机 7 + 跳转 4 + 面板快照 1 + 命令 2）；
    反向验证三组：摘掉代际守卫、列不夹取、内存覆盖退回磁盘读取——对应用例全红
