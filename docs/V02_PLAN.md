# wtmd v0.2 规划 — 让成文更美，让思绪更自由

> v0.1 解决了「思绪 ⇄ 成文」的双视图；v0.2 要让成文的一端更有质感，让思绪的表达更自由。

## 版本主题

四大特性对应产品哲学的落点：

| 特性 | 哲学落点 |
|---|---|
| 自定义 CSS 主题 | 开放可塑——主题是开放标准，社区可以塑造成文的样子 |
| 图片管理 | 写作即排版——粘贴即成文，思绪不必为路径分心 |
| 脚注 | 极简无干扰——正文保持心流，细节有处安放 |
| Mermaid 图表 | 纯文本本质——图表也是文本，永远可移植 |

## P0 — 核心特性（本版本必做）

### 1. 自定义 CSS 主题系统

**用户故事**：作为写作者，我希望成文的外观由我（或社区）定义，而不是只有默认样式。

- **主题格式**：一个主题 = 一个 `.wttheme` 文件夹，含 `theme.json`（名称/作者/深浅色声明）+ `light.css` + `dark.css`（可选）。基于现有 CSS 变量体系（`--bg`/`--fg`/`--accent`…），用户只需覆盖变量即可
- **内置主题扩充**：默认主题之外，新增 2 套——「纸墨」（衬线、暖白、书卷气）与「终端」（等宽、高对比、极客风）
- **主题选择 UI**：工具栏主题菜单 + 偏好设置面板预览
- **主题目录**：`~/Library/Application Support/wtmd/Themes/`，拖入即装
- **实现要点**：现有 `Theme.css` 拆分为「基础排版」+「变量主题层」两段注入；WebView 切主题只重载变量层不重排正文
- 工作量：M ｜ 测试：变量解析单测 + roundtrip

### 2. 图片管理（粘贴即成文）

**用户故事**：我截图/拖图进来，wtmd 自动落地为文件并插入相对路径链接，文档目录随拷随走。

- 拖拽/粘贴图片 → 自动存入 `<文档目录>/assets/`（无目录时提示选择）→ 光标处插入 `![](assets/xxx.png)`
- 文件名：`截图-20261009-143025.png` 风格（可在偏好设置改前缀）
- 预览中图片相对路径解析（`baseURL` 已支持，补全拖拽落地链路）
- 粘贴纯文本截图数据（NSPasteboard PNG/TIFF）转 PNG 编码
- 工作量：M ｜ 风险：非文件型粘贴板数据格式枚举

### 3. 脚注

**用户故事**：技术写作需要引用出处和补充说明，但不应打断正文。

- 语法：`[^id]` 引用 + `[^id]: 内容` 定义（支持任意 id，兼容 GFM）
- 渲染：正文 `<sup><a>` 上标 + 文末 `<section class="footnotes">` 自动汇总；编号按引用顺序
- 解析器：块级阶段剥离定义行（可出现在文档任意位置），行级阶段替换引用
- 大纲不受影响；导出 HTML/PDF 自动携带
- 工作量：M ｜ 测试：定义前置/后置、重复引用、未引用定义、嵌套内联标记

### 4. Mermaid 图表

**用户故事**：流程图、时序图是技术文档的刚需，且它们本质上就是文本。

- 语法：` ```mermaid ` 围栏代码块渲染为图
- **实现决策**：预览 WebView 注入 mermaid.js（本地内置资源，非 CDN——保持离线可用与隐私）。与「零第三方依赖」哲学的冲突说明：依赖指 Swift 包依赖；前端渲染资源本地内嵌、随源码仓库走，不违反「本地优先」
- 渲染失败降级：显示原代码块 + 错误提示，不白屏
- 导出：HTML 内嵌脚本可动；**PDF 打印时 mermaid 需等待渲染完成**（打印管线加就绪等待）
- 工作量：L ｜ 风险：JS 资源体积（~1MB）、打印时序

## 技术债与基建（随版本偿还）

1. **渲染管线异步化**：v0.1 的 250ms 防抖渲染在超长文档（>5000 行）会卡顿，v0.2 引入增量解析（按块 diff，只重渲染变化块）
2. **性能基准测试**：新增 10k 行样本的渲染耗时基准，防回归
3. **CI**：GitHub Actions 跑 `swift test`（macOS runner），PR 门禁
4. **发布物**：make-app.sh / make-dmg.sh（复用 Openly 已验证链路，v0.2 末尾搭，v0.3 首发 DMG）
