# wtmd v0.3 规划 — 从一篇文档，到一间书房

> v0.1 解决了「思绪 ⇄ 成文」的双视图；v0.2 让成文的一端更有质感；v0.3 要让 wtmd 从「打开一篇文档的工具」变成「写作的人愿意常驻的地方」。

**状态**：已发布（2026-10-16，详见 [V02_PLAN.md](V02_PLAN.md)）｜ 前置：v0.2.0 已发布（2026-10-16）

## 版本主题

v0.3 的特性全部指向同一个转变：**单文档工具 → 常驻写作工位**。

| 特性 | 哲学落点 |
|---|---|
| 文件夹工作区 | 本地优先——整个文件夹就是工作区，文件仍在磁盘上，Finder 与 wtmd 看到同一个世界 |
| 打字机模式 | 极简无干扰——视线不必追逐光标，光标永远停在视线中央 |
| 专注模式 | 极简无干扰——心流里只有当前这一段，其余退成背景 |
| 命令面板 | 写作即排版——所有能力一跳可达，界面因此可以更空 |
| DMG 分发 | 开放可塑——让更多人零门槛拿到 wtmd |

## P0 — 核心特性（本版本必做）

### 1. 文件夹工作区

**用户故事**：作为写作者，我希望把整个文件夹拖进 wtmd，侧栏出现文件树，像 Finder 一样工作，但写作体验属于 wtmd。

- 打开文件夹（⌘⇧O）→ 侧栏文件树（仅 `.md` / `.markdown`，子目录可折叠）
- 文件树随 Finder 变更刷新（FSEvents / DispatchSource 文件监听），外部新建、删除、重命名实时反映
- 点击切换文档：**文件模式编辑自动落盘**（1.2s 防抖；切换文档、新建、退出应用、关闭窗口前立即 flush，防抖窗口内的最后一笔不丢）；未命名文档仍走草稿
- 当前打开文件在树中高亮并跟随（reveal in tree）
- 单文档模式保留：不打开文件夹时仍是现有体验，侧栏只显示大纲
- **实现要点**：现 `DocumentStore` 是单文档模型，需引入 `WorkspaceStore`（工作区根 + 树状态 + 监听），`DocumentStore` 保持单文档职责不变；侧栏从「大纲」扩展为「工作区 / 大纲」两个分段
- 工作量：L ｜ 风险：文件监听的边界情况（重命名目录、外部删除正在编辑的文件）

### 2. 打字机模式 + 专注模式

**用户故事**：作为心流中的写作者，我希望光标永远停在屏幕中部（打字机），且当前段落之外的内容退成浅灰（专注）。

- 打字机模式：光标所在行垂直居中，滚动平滑跟随；设置项开关 + 快捷键
- 专注模式：源码视图当前段落正常显示，其余段落降透明度；预览不受影响
- 两者独立开关，可组合
- **实现要点**：光标行居中要自绘 `NSClipView` 覆写 `constrainBoundsRect` 让滚动范围多出半屏（否则文档末行永远只能贴底），且只对光标那一行 `ensureLayout`；专注走 layout manager 的**临时属性**，不碰 textStorage——现有高亮每次改动都重建整串属性，写进 textStorage 会被下一次高亮冲掉
  - ⚠️ 原计划「复用 `BlockDiff` 的块边界」**实际不可行**：那边的「块」已经是渲染好的 HTML 字符串，不带源码区间。改为按 Markdown 语义自行判定段落（连续非空行为一段），纯函数、可单测
- 工作量：M ｜ 测试：段落边界与光标归属的单元测试

### 3. 命令面板

**用户故事**：作为熟练用户，我希望 ⌘K 呼出面板，输入几个字母就执行任何命令——切主题、开关模式、导出、打开最近文件。

- ⌘K 呼出，模糊搜索，↑↓ 选择，↩ 执行，Esc 关闭
- 命令注册表：把现有菜单动作（新建/打开/保存/导出/主题/视图切换…）统一注册，面板与菜单共用同一来源，避免两处维护
- 支持最近文件直接从面板打开
- **实现要点**：SwiftUI overlay + 自研模糊匹配（子序列匹配 + 连续命中加权，零依赖）
- 工作量：M ｜ 测试：模糊匹配排序的单元测试

### 4. 首个对外 DMG

**用户故事**：作为新用户，我希望下载一个 .dmg，拖进「应用程序」就能用。

- `make-dmg.sh` 已就位（v0.2 验证过产物），本版本补齐发布件：
  - ~~Developer ID 签名 + notarytool 公证~~ **实际路线（2026-10-16 确认）：无证书路线**——本机只有 Apple Development 证书、没有 Developer ID，公证不可行。对外产物固定 ad-hoc 签名（`codesign --sign -`）：Apple Development 签名对陌生机器同样过不了 Gatekeeper，还携带 `get-task-allow` 调试 entitlement，对外分发是更差的产物。`WTMD_SIGN_IDENTITY` 可显式覆盖（make-app.sh 本机自用仍自动取可用证书）
  - Gatekeeper 引导：**macOS 15 起「右键 → 打开」已不再能绕过**未公证应用的首次拦截，引导只保留两条有效路径——「系统设置 › 隐私与安全性 › 仍要打开」与 `xattr -cr`。文案三处落地：DMG 背景图底部、README「安装」一节、打包完成后的分发提示
  - DMG 背景图（拖拽到 Applications 的箭头提示）✅：`Assets/gen_dmg_background.swift`（Swift + CoreGraphics，零第三方依赖，`tiffutil -cathidpicheck` 合成 HiDPI tiff），延续图标「断续虚线 → 连续实线」意象，底部直接印上首启引导。图标位置等布局常量与 `make-dmg.sh` 两侧同步
  - Finder 布局（窗口尺寸/图标位置/背景图）**直接写入卷内 `.DS_Store`**（`Assets/write_dmg_layout.py`，bwsp/icvp/icvl/Iloc，配方与 dmgbuild 同源）——最初用 osascript 控制 Finder，但 Apple Events 需要 TCC 授权且在受限/无头环境拿不到（实测 -1743），遂改为直接写文件：零自动化依赖，CI 也能产出带布局的 DMG；Python 依赖（ds_store/mac_alias）缺失时降级为默认视图
- Release 产物：`.dmg` 附到 GitHub Release
- 工作量：S（有证书）/ M（无证书走引导文案路线）

## P1 — 顺延到 v0.4

已确认：v0.3.0-rc 只做命令面板，下面两项与 P2 一起挪到 v0.4 各自独立开工（KaTeX 那块要先验证与增量渲染不变式的兼容性，不夹在发布前做）。

### 5. `[TOC]` 目录语法

- `[TOC]` 占位行渲染为可点击目录（标题锚点跳转）
- 解析器：块级阶段识别占位，渲染时注入大纲（AST 已有标题信息，零额外解析）
- 导出 HTML 携带静态目录
- 工作量：S–M ｜ 测试：占位识别、空标题文档、标题变更后 TOC 同步

### 6. 数学公式（KaTeX）

- `$...$` 行内 / `$$...$$` 块级，渲染为公式
- 实现路线复用 mermaid 模式：katex.min.js + 字体本地内嵌、**按需注入**（仅文档含公式时）、渲染失败降级为原文本
- 需先验证 KaTeX 与现有增量渲染不变式的兼容性（不得增删 `#wtmd-content` 顶层子节点，失败节点要清理——mermaid 的教训直接平移）
- 工作量：M ｜ 风险：资源体积（JS + 字体）、增量渲染适配
